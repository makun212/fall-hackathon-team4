# Issue #78：会話の教材範囲をサーバー側で固定する修正

起点：2026-11-09時点の `origin/main`、`f8e049f`。
ブランチ：`fix/issue-78-conversation-scope`。すべて未ステージ・未コミット。

## 変更

- 継続時のロール・本文は、会話に保存した `material_set_id` から取得する。
- Cookieは保存済みIDとの一致確認だけに使う。削除・別セットへの変更・不明なセットは400で拒否し、全文へフォールバックしない。
- 教材セット未選択の全文モードも固定し、途中から別セットへ変更できないようにする。
- 問いかけ画面だけでなく、直接チャット画面を開いた時点でも会話の文脈を保存する。
- 直接POSTの初回もAI呼び出し前にDBで文脈を固定する。同じIDの同時要求で、別セットへの上書きを許さない。
- 不正な要求ではAIを呼ばず、会話の既存の考え・メッセージを書き換えない。

## 既存DB・APIとの互換性

URL・フォーム・ロールID・既存のDB列・返答形式・依存ライブラリは変更していない。
frontendは変更していない。main.py、db.pyの公開済み関数の既存引数を変更していない。

`conversation_contexts` テーブルを追加し、新しい会話で本文範囲を固定したことを記録する。
既存テーブルのALTER・削除や既存行の自動書き換えは行わない。既存の `metadata.create_all()` で不足テーブルだけを追加する。
SQLiteで旧スキーマに追加し、既存データが変わらないことをテストした。Postgres・本番環境は未検証。

旧会話の `material_set_id=NULL` は、全文モードだったのか、旧直接チャットの保存漏れか区別できない。
固定記録のないNULLの旧会話は400で拒否する。推測で全文へ広げたり、現在のCookieで範囲を補完したりしない。
該当する場合は教材とロールを選び直し、新しい会話を開始する必要がある。旧データは残る。
保存済みのセットIDがある旧会話は、そのセットで継続可能。

会話ID発行時にメタデータを保存するため、直接チャットを開いただけの未発言の会話もDBに作られる。
AI失敗時は固定済みの文脈を保持し、失敗した発言・返答は履歴に保存しない。
